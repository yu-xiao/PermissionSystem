## 2. 首批范围 [Architect]

新增独立开发工具工程 `backend/PermissionSystem.AiEvaluations`，复用现有 .NET 10、System.Text.Json 和项目引用；隔离夹具沿用项目已使用的 EF Core InMemory，不引入新的依赖种类、Agent 框架或管理页面。API、Worker、Application、Domain 不反向依赖该工具。

工具工程组合现有 `AiConversationService`、`AiReadOnlyToolRegistry`、权限诊断、结构化结果读取和追问服务。业务查询、权限和数据范围仍执行原服务；替换的是存储环境、测试身份及离线模型网关，不是授权结论。

首批主场景为权限排障，并纳入少量用户搜索及追问案例验证歧义、无数据和结构化证据。模型可见的只读工具目录使用现有注册器按测试身份计算，包含现有可用查询工具，避免只提供一个目标工具导致选择评测失真；未启用的报表仍关闭。实际工具目录进入报告与摘要。

首批不注册动作处理器、不授予草稿／执行权限；不连接实际业务数据库、Redis、RabbitMQ，不写生产业务数据。SQL Server、HTTP／OpenIddict 端到端认证和浏览器体验继续由既有环境验收处理，隔离身份夹具不能证明实际登录链路通过。

### 2.2 案例契约与人工审核

版本控制的案例 JSON 保存：案例 ID／版本／分类、自然语言输入或多轮步骤、合成身份／租户／数据夹具引用、预期工具与调用次数约束、允许的参数及实际生效条件、必须／禁止的事实、结论与证据来源、预期错误／澄清行为、离线响应脚本、真实模型适用性、人工审核记录。

预期结论依据现有业务计算和人工审核固定，不能从本次待测输出反向生成预期。人工审核记录初始为待审核；助手补充夹具和预期不等于业务 Owner 已确认黄金基线。

人工审核模板明确记录审核者、日期、原始负反馈的脱敏引用、确认的问题、修订后的案例及依据。只接受人工筛选且脱敏的内容，禁止直接搬运用户会话、Token 或生产证据；不自动训练或发布。

## 3. 执行、报告与比较 [Architect]

### 3.1 两种执行模式

- **离线**：默认模式；无网络、无供应商费用。使用合成身份和每案例独立的 InMemory 数据库，脚本化网关驱动真实用例编排；固定数据、绝对时间及参数，动态 Run／Invocation ID 单独标注或规范化。测试服务端约束、证据、错误、预算和报告判定，不宣称评测了模型能力。
- **真实模型**：显式选择才可启动；同一隔离夹具和编排，仅将网关替换为既有真实网关。使用经确认的供应商、模型与网络策略，密钥由进程环境读取，不放命令参数、夹具或报告。不给模型真实用户数据。供应商协议、网络和数据政策仍需要管理员确认。

每个案例新建隔离环境；多轮步骤仅共享该案例自身的会话。执行不自动重试整条案例以挑选成功结果；编排内部既有重试／备用路由如实际启用，完整记录所有请求并纳入预算。首批真实模型单路由、串行执行，以便归因。

### 3.2 判定与人工事实复核

自动检查：实际工具选择与调用状态、模型提出参数及服务端生效参数、结构化结论、证据来源、范围／过滤、引用归属、截断和错误／澄清行为。报告同时记录参数提出阶段与执行阶段，不能将服务端纠正后的参数当作模型选择完全正确。

自然语言检查使用案例指定的禁止事实与可验证约束作为辅助，不以关键词命中声称完成全部语义判断。解释是否与证据一致、是否捏造原因、是否充分表达限制，由人工审核最终确定；判定包含通过、失败、待人工审核、不适用、未执行／预算终止。模型自评分不作为唯一依据，首批不增加评审模型调用。

检查器自身测试包含故意违反预期的输出，验证误调用、错误结论、泄露合成不可见标记、缺证据及伪造事实能被判为失败。该类测试不能全部依赖模型“刚好回答正确”。

### 3.3 报告内容

生成机器可读 JSON 及便于审核的 Markdown，保存：

- 案例／夹具／检查器版本和摘要、执行模式、时间与环境说明、代码 Git 提交及工作区是否有变更；另记录相关源码内容摘要，不能只写 HEAD。
- 实际模型配置：供应商别名、请求及响应模型、temperature、maxTokens、超时、实际调用次数；剔除密钥、认证头、完整端点和原始异常正文。
- 从实际请求获得的系统 Prompt 摘要、Agent／Prompt 版本、工具版本、描述及输入／输出 Schema 摘要、实际提供给模型的工具集合。澄清或权限拒绝在模型请求前结束时，明确记录未调用，不伪造请求快照。
- 脱敏输入／输出、模型工具参数、服务端实际参数、服务端证据和来源、每个检查的判定与理由、人工审核状态、耗时、Token usage／估算、费用币种和估算／未知标志。

所有输入仅来自受控合成夹具；报告再进行敏感字段与内容裁剪，异常只保留错误分类及受控摘要。脱敏和裁剪状态可见；因裁剪或不支持检查导致无法证明通过时标记待审核／失败，不能静默当作通过。

本地产物写入独立 `artifacts/ai-evaluations/`，不覆盖已有报告，不默认提交真实模型输出；CI 只上传合成离线报告。文档中的已审核基线／摘要可进入版本控制，人工审核更改通过独立审核文件关联报告摘要，保留原始自动判定。

### 3.4 前后对比

支持以已保存报告作为 baseline 与 candidate 对比，不重写旧报告。核对执行模式、案例 ID／内容摘要、夹具、检查器版本及模型采样配置的可比性；模型／Prompt／工具／代码版本是允许变化且必须明确展示的比较维度。

案例变化、缺失、重复、执行范围变化、未执行、预算终止及人工待审核不能消失在汇总分母中；不可比较时明确阻止给出发布通过结论。输出逐案例退步、新增失败、安全失败、参数／事实正确率、耗时与按币种费用变化。离线报告不能充当真实模型基线，首次真实模型报告人工确认后才形成该模式基线。

## 4. 首批门槛与预算建议 [Architect]

以下门槛随本方案确认，不视为已存在或已验证的业务标准：

1. 离线确定性检查全部通过；案例集及关键预期完成人工审核，缺项不能通过发布评测。
2. 越权、跨租户、敏感证据泄露以及错误声明写入等安全案例零失败；所有安全子用例均执行且通过，不能被总体正确率抵消。
3. 真实模型适用案例的工具／参数正确性及事实正确性分别不低于 **95%**，并且相对已确认、可比较基线无新增案例退步；安全案例仍要求 100%。非模型适用的异常注入用例单独统计。
4. 自然语言事实审核未完成、费用／执行不完整或 baseline 不可比较时，报告不得给出“发布通过”。阈值调整或案例移除需要说明理由并重新确认。
5. 首批只交付本地／CI 门槛检查和报告退出码，不接管生产发布；AIC-005 再接不可变发布快照及正式发布流程。

预算控制：离线默认；真实模式必须显式提供调用上限、Token 上限、费用估算上限、单一币种及输入／输出单价，并验证配置有效后才发请求，无隐含付费默认值。建议首轮串行、每条最多沿用现有 6 轮／10 次工具／90 秒限制，总预算由用户在执行真实模型前确认。

每次请求前预留预计输入和最大输出对应的 Token／费用；失败、重试和缺失 usage 仍计入调用及保守预留，不按零结算。达到上限立即停止后续请求并写出未执行原因，不自动加预算或隐藏失败。

现有输入 Token 估算不是供应商账单的数学上界，因此费用上限是**受控估算预算，不承诺实际账单绝不超额**；报告明确此限制。需严格账单限额时同时使用供应商端限额。本轮不调用付费供应商，后续真实执行需要明确配置和预算。

## 5. 数据影响 [DBA]

结论：**无数据库结构变更、无 EF 迁移、无权限种子或生产数据变更**。

案例和报告为文件；隔离夹具使用 InMemory，不读取连接串、不启动应用迁移／生产种子初始化。复用现有实体、EF 过滤、租户和诊断授权逻辑；测试身份只用于隔离进程，不是新增认证方案。

报告存储与现有会话保留策略无耦合，不复制生产会话或反馈。报告由使用者管理保留期与访问权限；仅审核后的脱敏摘要可提交。InMemory 无法证明 SQL Server 翻译、事务／并发、索引与性能通过，明确列为验证限制。

回退只涉及开发工具、案例和 CI；没有 Down、数据清理或生产服务切换。保留已有 `artifacts/` 和用户工作区改动。
