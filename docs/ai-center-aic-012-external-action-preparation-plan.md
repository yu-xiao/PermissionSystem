## 1. 首批建议与业务缺口 [Architect]

方向 2 的启动条件是一个明确的真实外部动作及 Owner、正式接口、审批和结果核对规则。当前没有选定目标系统、单据／动作、正式输入输出、目标幂等保证或人工补偿契约。本批按用户选择完成单一动作的接入契约填写项和恢复验收材料；有真实需求时填写第 3 节后，提交具体实现方案确认。

后续真实首批限于一个系统、一个动作、一种确定协议和经批准的调用主体。人工预览／确认、业务审批、逐次授权和结果审计是不同职责，聊天中的“确认”不能替代业务操作中的确认凭证或审批。向外部 MCP 客户端开放执行与仅内部使用分别评审，后台自动执行和自动补偿另行立项。

## 4. 执行与恢复语义草案 [Architect]

以下是必须在具体实现方案中落实的语义，**不是已新增的枚举、实体或自动恢复程序**。最终状态、字段及转换依据目标接口定义，不提前固定通用工作流。

| 阶段／结果       | 所需证据与行为                                                                                                       | 再次写入限制                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 已受理、待发送   | 当前授权／活动租户／数据范围、有效人工确认与审批；冻结已校验 Payload、处理器／映射版本及逻辑操作标识，持久化提交成功 | 同一逻辑操作重复入口只能返回既有状态；恢复须有可靠未发送依据及最新授权 |
| 已开始发送       | 发送前持久化单次尝试与并发认领，网络写入在短本地事务之外                                                             | 进程丢失、租约过期或客户端取消不能直接使另一执行者再次发送             |
| 目标处理中       | 正式协议明确受理但尚未完成，保存受控目标引用                                                                         | 受理不计成功；仅按批准契约查询，不能再创建一个操作                     |
| 已成功           | 目标正式结果证明此逻辑操作成功，目标归属／请求绑定一致；本地持久化业务结果与审计                                     | 重复请求复核访问后返回原受控结果，不生成第二个业务效果                 |
| 确定拒绝／未执行 | 正式协议或可靠证据证明没有业务效果，区分校验拒绝与可恢复故障                                                         | 是否允许修正后重新确认／提交由动作契约决定，不由一般 HTTP 错误码推定   |
| 结果不明         | 可能已发出但未得到可验证终态，或远端成功后本地记录失败；保持原操作／目标键与尝试证据                                 | 禁止以新确认版本、新键、超时或通用重试重新写入；先核对目标结果         |
| 人工核对待处置   | 目标暂不可查、证据不足／冲突、键过期或核对超期；保留不明状态及处置责任                                               | 人工记录不能凭主观判断改成“失败可重试”；补偿为另一个需批准的业务动作   |

准备方案建议后续首个真实批次先支持人工发起受控只读核对，不预设后台轮询或自动补偿。目标查询未查到可能来自延迟或查询权限不足，不视为确定未执行；429、5xx、连接断开、客户端取消或查询超时同样不能单凭状态断言外部未写入。

逻辑操作标识、目标幂等键、PayloadHash、目标范围及确认／审批证据应形成稳定绑定。一个尚未核对的不明操作不得通过重新确认绕过重复保护；映射、字段、处理器或业务版本变化须按契约重新校验，旧操作保留原绑定和核对路径。撤权／停租户后不继续新写入，结果读取／核对及人工处置使用明确权限和主体，不保存或重用用户 Access Token。

本地事务只保护本地意图、确认消费、执行记录和审计一致性；需证明意图提交后才允许发出请求。目标已写入、本地保存失败必须按原标识核对；本地 Down、删除记录、草稿取消或 Outbox 清理均不能撤销远端业务效果。

## 5. 分层与预计影响位置 [Architect]

1. Application 的 `AiActions/` 负责单一动作编排、逐次授权／审批／确认、意图和尝试生命周期及受控结果核对。沿用现有注册／访问策略，保持现有 Demo 入口契约；不直接在 Demo 服务中增加网络写入分支。
2. Domain 仅表达已确认业务规则与持久化状态，不依赖 HTTP、EF 或调度器；Infrastructure 实现目标协议、受保护凭据、固定出站策略及执行／核对存储接口。Controller 使用 DTO、ApiResult／PagedResult 和 CancellationToken，不访问 AppDbContext。
3. 新 UI 如确需，复用既有草稿卡片、Axios、权限及主动确认交互，但按真实 schema 设计；结果不明必须有明确状态和核对入口，不能显示普通失败及重试按钮。现有 Demo 强类型 DTO 是否扩展由具体契约评审。
4. 新动作／结果须显式纳入场景及工具白名单，按 AIC-003／004／005 的契约、评测和新版本发布治理完成验收。模型工具只准备草稿，正式执行由经授权的人类入口发起；后台身份与恢复兼容单独确认。

预计影响 Application 的 `AiActions/`、Infrastructure 的单一目标适配／持久化与 DI，必要的 Domain 实体／映射／迁移、API 和人工处置界面，以及 UnitTests／IntegrationTests 的 `AiCenter/`。当前不预定新表名、接口名、权限码、具体 DTO、SDK 或配置参数；在目标动作契约确定后列出实际文件和最小变更。

## 6. 数据影响、兼容与回退 [DBA]

**准备批次无数据库变更。** 本轮仅文档，未新增实体、表、索引、种子或迁移，未连接业务系统。

真实动作批次很可能需要持久化逻辑操作、尝试、稳定目标键、身份映射版本、结果引用和核对／人工处置证据。是否扩展现有执行表或新增单一动作存储，由真实契约评审；不能把现有 Failed 直接解释成外部未执行，也不能将旧 Demo 行伪造为外部记录。

新增实体默认继承 BaseEntity。评审 TenantId、审计／软删除、rowversion、租户组合关联和唯一约束、状态／时间索引、有界扫描及证据保留。现有唯一索引过滤 IsDeleted，需单独证明外部逻辑操作及目标键不会因软删除／清理而被复用；未决记录、幂等作用域与目标键有效期不能被普通留存任务破坏。

迁移设计优先增量兼容，生成增量审核 SQL 并在隔离环境验证；实施、真实迁移和目标写入不是同一授权。回退停用新动作及出站写许可，保留未决状态、操作键和审计，由获准主体继续核对／人工处置；不清表、不破坏性 Down，不承诺撤回已发生的外部效果。

### 7.1 恢复用例准备表

以下用例均为待执行的验收设计，当前没有运行测试或外部请求。故障类用例优先在批准的离线协议替身中模拟；真实目标环境只验证经 Owner 批准的隔离业务操作，不对网络或生产服务制造故障。

| 用例                   | 准备条件                                                       | 预期结果与需留证的内容                                                                                   |
| ---------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 意图保存失败           | 本地意图提交失败，协议替身记录调用计数                         | 不发生目标写调用；保留准入／保存失败证据                                                                 |
| 同一操作重复入口       | 同一冻结 Payload 与目标范围，重复请求／确认，HTTP 请求键可不同 | 只有一个逻辑操作；依契约返回既有状态，不能产生新的目标业务效果；记录操作绑定、实际尝试数及目标结果       |
| 发送标记后中断         | 已保存发送尝试，但本地无法证明是否发出                         | 进入不明／待核对语义；认领过期或重启不能直接触发再次写入；保留标记与核对证据                             |
| 远端成功但响应丢失     | 协议替身已产生业务结果，调用方收到超时或断开                   | 保留原键与不明状态；受控核对找到同一归属／Payload 结果后记成功；再次确认不能生成第二个结果               |
| 远端成功、本地保存失败 | 目标正式成功，本地终态提交失败                                 | 不把本地异常视为外部未执行；按原逻辑标识核对并恢复真实结果与审计                                         |
| 目标已受理未完成       | 正式契约提供处理中结果及可查询引用                             | 状态为目标处理中，不能显示已成功或提供新写重试；只按批准方式查询终态                                     |
| 查询暂未找到／不可用   | 目标延迟、查询权限不足或查询超时，证据不足                     | 保持不明；记录原因、时间和责任人，不能凭空记失败或生成新键                                               |
| 结果范围／请求不匹配   | 查询返回其他租户／账套、不同 Payload 或冲突业务结果            | 拒绝将其作为成功证据，不暴露越界内容；进入人工核对，保留安全摘要                                         |
| 确认后撤权／范围变更   | 确认已存在，发送前最新权限、租户状态或映射改变                 | 停止新写入；旧未决操作保留原绑定，由获准主体处理，不因重映射而改写目标                                   |
| 幂等期限届满／人工超期 | 未决操作的目标键或核对时限达到契约边界                         | 不自动换键或重发；转人工处置，证据仍保留；补偿须独立正式规则及确认                                       |
| 本地重复消费／事务重放 | 同一操作被重复认领或本地事务委托再次执行                       | 本地重放不包含目标写请求；持久化绑定与并发保证仍成立；记录实际网络尝试及业务效果，不能只统计 HTTP 返回数 |
| 取消／停用／回退       | 发送后取消或关闭功能，目标结果可能已发生                       | 不宣称已撤销远端效果；保留结果核对路径、权限与审计，界面禁止普通新写重试                                 |

### 7.2 单次验收与人工处置证据模板

每个用例分别填写下列项目，空缺写“待提供／未执行／不适用及原因”。证据仅包含经批准的白名单、摘要和引用，不包含秘密或完整业务正文；待提供的期限与人员不从 Demo 或其他批次推定。

| 证据项         | 待填写内容                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 契约与代码基线 | 目标系统／动作、协议及业务版本、实现提交／构建、用例编号、环境与测试数据版本                           |
| 执行依据       | 获准租户／目标范围引用、调用主体、业务权限、确认／审批证据引用、Payload 摘要与逻辑操作绑定             |
| 故障与观察     | UTC 时间、模拟条件或实际观察、冻结键的受控引用、尝试／认领记录、目标调用计数、实际业务效果及当前状态   |
| 核对依据       | 正式目标查询方式与契约版本、查询人权限、查询时间、目标结果引用、归属／请求匹配结论、证据位置           |
| 人工处置       | 未决原因、责任人、期限、审核人、处置结论及依据；需补偿时填写独立批准动作与关联证据，不能覆盖原操作历史 |
| 退出结论       | 通过／失败／跳过／阻塞、原因、复核人及签认时间、待办；未执行不得标通过                                 |

准备范围退出条件：契约填写项、状态与禁止重放边界、恢复用例及证据模板完整，并通过静态复核／引用／格式／差异检查。具体实现退出条件仍为第 3 节材料及实际实现方案确认；目标环境退出条件另须真实验收和 Owner 签认，三者分别记录。
