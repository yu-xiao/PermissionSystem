# AI 中心与 Swagger P1 安全调整

## AI 请求

聊天、备用供应商与测试连接统一使用安全 HTTP 传输：

- 禁止自动跟随重定向；供应商配置须填写最终接口地址。
- DNS 地址通过校验后绑定到当前请求，Socket 直接连接该 IP，连接阶段不再次按主机名解析。
- 保留原请求主机名和默认 HTTPS 证书校验。
- 禁用系统代理、Cookie 容器和跨请求连接复用，避免旧连接或代理绕过当前请求的地址策略。使用 HTTP/1.1。
- 默认阻止私网、回环及保留地址；本地模型仍需显式启用“允许私网”和相应 HTTP 设置。
- 合成后的完整接口 URL 仍必须属于配置的源，不允许接口路径附带查询参数或片段。

每次请求重新建立连接会增加握手开销。需要代理才能访问的模型服务在此策略下不可达，应部署可直接访问且明确受信任的模型网关，不应通过关闭证书校验恢复连接。

## Swagger OAuth

Swagger 使用独立公共客户端 `permission-swagger`，只提供授权码 PKCE 流程，客户端没有密钥，不开放密码或客户端凭据授权。原有用户登录、租户校验及授权确认继续由 OpenIddict 和现有登录入口处理。

开发配置项：

- `Swagger:TenantCode`：调试使用的租户，默认 `default`。
- `Swagger:OAuthRedirectUris`：明确登记的 Swagger 回调地址。默认与项目启动配置一致，为 `http://localhost:5264/swagger/oauth2-redirect.html` 和 `https://localhost:7281/swagger/oauth2-redirect.html`。

使用其他端口、主机名或反向代理路径时，需登记对应的精确回调 URL。非回环地址必须使用 HTTPS，不接受通配符、查询串、片段或 URL 用户信息。

重启开发 API 后，现有初始化流程会创建或更新此客户端；同名非公共客户端会触发错误而不是被覆盖。本次没有数据库结构迁移，也没有直接修改运行中数据库。

## 历史密钥与验证范围

移除 Swagger 密钥下发不能撤销此前已经泄露的 `permission-admin` 客户端密钥。本次未自动轮换该密钥，以免中断其现有调用方。应同步轮换开发配置和所有调用方使用的密钥，并按实际泄露范围评估已签发凭据。

验证使用合成凭据和本机临时 TCP/TLS 服务，覆盖重定向不跟随、校验地址直连、私网策略、连接复用隔离、未受信任证书拒绝，以及 Swagger 公共客户端、PKCE、回调地址和密钥不下发。未对真实供应商或真实数据库执行认证联调。
