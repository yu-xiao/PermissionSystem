## 1. 现状与范围 [Architect]

- AIC-007 已提供 `IDemoBusinessOrderReadOnlyQueryService`，支持当前审批状态、授权范围过滤和完整计数；Demo 环境验收尚未完成，真实业务批次仍待确认。
- `ScheduledTaskService` 当前只允许 `DemoLog`，通过 `IBackgroundJobService` 使用 Hangfire，并参与租户停用／恢复和启动同步。现有周期任务使用服务器本地时区，新任务不能依赖此隐含配置。
- `NotificationService` 已支持 Direct、OutboxRabbitMQ、Disabled。空接收人列表具有全租户广播语义；Direct 当前先保存再发送 SignalR，SignalR 失败可能发生在数据库已提交之后。
- 通知读取只校验个人通知归属，不重新检查 Demo 业务权限。Outbox 消费会重新解析有效用户，但不检查 Demo 数据范围。
- 既有 `AiAlertService` 负责组件熔断／恢复，不是业务异常提醒，不将新规则直接并入其管理员广播逻辑。
- AIC-008 会话后台身份依赖登录会话和 SecurityStamp，不直接拿它充当永久周期任务授权。

本批只实现确定性 Demo 提醒，复用现有认证、权限计算、数据范围、调度、站内通知、Outbox／Inbox 和日志。不新增依赖，不接入真实 ERP／WMS，不赋予模型执行、授权或审批能力。

## 3. 分层与调度 [Architect]

1. Domain 新增规则及异常事件实体，继承 `BaseEntity`；状态转换保持确定性，不依赖 EF、Hangfire、HTTP 或模型。
2. Application 新增 `AiAnomalies` 用例：创建／读取、暂停／恢复、立即检查、事件列表／详情、关闭事件及受控任务执行。Controller 只处理 DTO、协议、既有 Permission 策略和 CancellationToken。
3. 周期任务绑定既有 `ScheduledTask`，新增固定受控任务类型 `AiDemoPendingReminder`。规则入口创建关联任务；通用定时任务入口不得通过修改 JobType、ParametersJson、租户或任务绑定绕过规则用例。通用任务仍只允许原 DemoLog 的任意参数。
4. 对 AIC-011 绑定任务的通用修改／启用／触发／删除入口进行约束，统一走同一规则验证；启动同步、租户停用／恢复按新受控类型调度。原 DemoLog 行为与时区保持兼容。
5. 调度只携带任务 ID，运行时从持久化配置加载用户、租户和规则。系统范围仅用于定位任务和必要维护，业务查询在独立、明确租户及当前身份的 DI scope 中执行，退出系统范围后调用 Demo 公开只读用例。
6. 复用 `IUserCredentialValidator.GetAuthenticationStateAsync`、租户状态与现有权限计算，重新构造当前用户及审计上下文，再调用 `IDemoBusinessOrderReadOnlyQueryService`。不保存密码、Token、Cookie 或登录会话，不假造超级管理员。
7. 首批周期授权是创建人显式启用的持久化个人规则，不依赖浏览器登录持续有效；用户／租户停用、业务权限或规则权限撤销立即使后续执行拒绝。该授权语义须随本方案一起确认。
8. 复用分布式锁减少重叠，数据库 rowversion、唯一约束和事务作为最终幂等边界；不能把锁当成恰好一次保证。查询使用取消及有界超时，锁超时记为跳过，失败记脱敏错误码及 TraceId。

## 4. 权限与证据 [Architect]

- 首批复用已有 `system:scheduled-task:view/create/update/trigger`，分别控制读取、创建、修改／暂停／关闭、立即检查；业务证据另要求 `demo-business-order:view`，通知可用性检查已有 `system:notification:view`。不新增平行权限体系，也不自动授予这些权限。
- Application 自身验证同租户、规则创建人归属和操作权限，不仅依赖 Controller。超级管理员的本批业务查询仍显式限当前租户；拥有定时任务管理权限不意味着可以读取别人的业务证据。
- 规则创建／启用／运行继续要求 AI 中心及新提醒功能开关开启、当前租户位于批准列表；读取和关闭遵守现有权限与安全停用语义，不因总开关关闭失去停止任务的入口。
- 执行前、查询后、通知投递前重新核对身份、权限、范围、规则版本、启停状态和功能开关。检查中发生变化则本次结果不输出，不使用历史 claims 或事件作为授权凭据。
- 证据只保存完整数量、固定查询口径、观察时间、规则版本和范围指纹；不持久化客户、金额、负责人、标题或截断明细。范围指纹不能替代逐次授权。
- 通知标题、正文、Payload、LinkUrl 仅携带通用提示及不透明事件引用，不含单据、数量、部门、用户名、规则名称等业务证据。前端打开事件后经专用 API 重新授权读取。
- 历史事件读取重新验证当前业务范围；范围变化时遮蔽旧数量，提示重新检查，不能将新查询值冒充历史观测值。停用／撤权后不返回旧敏感证据。
- 通用任务日志与运行错误只保存安全状态、错误码和引用；业务数量不进入可被其他任务管理员读取的日志。

## 5. 通知可靠性与失败语义 [Architect]

1. 明确绑定且非空的单个接收人；接收人无效或撤权时记录拒绝，绝不调用通知服务的空列表广播路径。
2. 先可靠记录确定性异常事实，再尝试投递；通知失败不丢异常、不改判定，也不将失败视作已成功通知。无异常只记录安全执行状态，不创建通知、不调用模型。
3. 为既有通知服务补受控幂等发送入口：由事件生成稳定 DeliveryKey，Direct 使用持久化通知唯一键，Outbox 使用稳定 MessageId，重复调度／重试／消费仍指向同一效果。
4. Direct 的通知保存与事件投递状态、冷却更新时间在同一事务内落库；实时推送在提交后尽力发送。推送失败不得重建通知，可通过既有个人通知列表读取。
5. Outbox 的入队、事件关联与冷却预留在同一事务内完成；状态明确区分“已入队”和“已持久化投递”，不把 Queued 记成 Delivered。投递详情通过已有 Outbox／Inbox 状态关联反映失败和人工处理入口。
6. Outbox 延迟消费时，对 AIC-011 来源引用再运行接收人／规则／范围授权检查；撤权、暂停或关闭使该投递被抑制并记录结果。将受控来源检查扩展到既有通知流水线，普通通知不改变原语义。
7. Disabled 记为通知禁用，不标记成功或消耗成功冷却；只重试当前仍有效的异常，不在恢复后补发过期提醒。每个事件最多 3 次发送尝试，失败后分别退避 5／15 分钟，到达上限进入人工处理状态，立即检查不能无限重试。Outbox 已可靠入队后不重复创建发送尝试，其运输重试沿用消息设施；终态失败释放发送冷却预留，但保留事件幂等键与尝试上限。
8. 开关关闭、规则暂停、租户停用和人工关闭均不能清空已存在的幂等键或冷却状态；规则恢复后从最新确定性查询继续。
