# EA-021 查询性能基线

## 1. 范围与口径

- 日期：2026-08-10
- 数据规模：专项测试使用 25 个用户、100 个工作流任务/实例、30 个报表定义、40 条 Outbox 和 50 个 API Client/调用日志。
- 页大小：除特别说明外均为 10。
- SQL 数量口径：一次 `IAsyncQueryExecutor` 终止操作对应生产 EF Core 的一次数据库执行；测试固定执行次数，防止 N+1 回归。
- 物化口径：记录 `ToListAsync` 实际返回到 Application 的行数；`LongCountAsync` 不计入物化行数。
- 耗时口径：本机 EF/InMemory 代码路径测试耗时，只用于版本间回归，不代表 SQL Server 生产延迟。
- 内存口径：记录物化行数和已排除的大字段字符下界，不使用不稳定的进程级 GC 分配量作为硬断言。

## 2. 修改前后对比

| 查询路径 | 修改前 | 修改后 | 回归约束 |
| --- | --- | --- | --- |
| 用户列表，10 行 | 22 次：计数 1、分页 1、每用户角色 ID/编码各 1 | 3 次：计数、分页投影、当前页用户角色关联 | 执行次数固定为 3；只物化 10 个用户和 10 个角色关联；不读取 `PasswordHash` |
| 角色列表 | 2 次，读取完整实体 | 2 次，直接投影 DTO | 保留 `IsSuperAdminRole`、内置标记和排序语义 |
| 工作流待办，100 条命中、取 10 条 | 2 次，但先物化 100 个任务，再物化 100 个实例并内存分页 | 2 次：数据库计数和关联分页，只物化 10 条结果 | 执行次数固定为 2；列表不读取 100 个实例中的 `FormDataJson` |
| 报表列表，10 行 | 12 次：计数 1、分页 1、每行参数 1 | 2 次：计数和轻量分页投影 | 执行次数固定为 2；不读取 81,920 个 `ColumnsJson/ParamsJson` 测试字符及参数集合 |
| 操作/登录日志 | 2 次，先读取实体再映射 | 2 次，数据库 DTO 投影 | 操作日志列表不读取 Request/Response Body |
| Outbox，10 行 | 2 次，读取 Payload 和 Headers | 2 次，轻量 DTO 投影 | 不读取 122,880 个 Payload/Headers 测试字符；详情按 ID 加载 |
| Inbox，10 行 | 2 次，同步执行 | 2 次，异步投影 | 分页发生在物化前；幂等判断和消息定位可取消异步执行 |
| API 调用日志，50 个 Client、取 10 行 | 3 次，预加载全部 50 个 Client | 3 次，只加载当前页涉及的 10 个 Client | 执行次数固定为 3；Client 物化上界等于当前页去重 Client 数 |

## 4. DBA 结论

- 无数据库结构变更，无新增 Migration。
- EF Core 模型与最后一个 Migration 一致。
- 复用现有用户角色、工作流任务、日志、Outbox/Inbox、报表执行日志和 API 调用日志索引。
- 未凭代码形态新增索引。索引调整必须以真实 SQL Server 执行计划、逻辑读和数据分布为依据。

## 5. 未覆盖项

- 当前环境未提供真实 SQL Server 测试连接，因此没有生产数据规模下的执行计划、逻辑读、数据库 CPU、内存授予和网络往返数据。
- InMemory 耗时不能作为容量规划依据；上线前应在预发布环境使用脱敏且接近生产规模的数据复测。
- `%keyword%` 模糊查询在普通 B-tree 索引下可能扫描，需根据真实使用频率评估全文索引或更明确的查询条件。
