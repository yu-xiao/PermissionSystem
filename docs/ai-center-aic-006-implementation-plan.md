## 3. 首批指标与查询契约 [Architect]

建议新增代码批准的数据集键 `system-users-scoped`，对应专用 `reporting.AiSystemUsers` 视图。名称和标识为本次拟新增项，不表示仓库已经存在。

数据源为当前租户 `Users` 的非软删除记录，一名用户按用户 ID 计一人，不连接角色表，避免多角色重复计数。包含内置用户；启用／停用完全采用 `User.IsEnabled`，不将锁定、登录失败或离线状态归类为停用。

| 指标代码（建议） | 定义 | 空数据 | 单位 |
| --- | --- | --- | --- |
| `user-count` | 服务端租户、授权范围和全部业务筛选执行后匹配的用户总人数 | 0 | 人 |
| `enabled-user-count` | 同一匹配集内 `IsEnabled = true` 的人数 | 0 | 人 |
| `disabled-user-count` | 同一匹配集内 `IsEnabled = false` 的人数 | 0 | 人 |

三个指标共用一个基础匹配集，因此指定“仅启用用户”后，停用人数为 0，不另查未筛选总体。总人数必须等于启用人数与停用人数之和。

维度建议仅允许：无分组、启用状态、部门 ID，每次最多一个维度。按部门统计仍是每组的三个指标，不做交叉维度、占比、金额、趋势或自定义公式。

- 部门维度按用户当前 `DepartmentId` 归属；空值单列“未分配部门”，不能悄悄丢弃或合并到某个真实部门。
- 首批不扩展部门名称目录，不通过部门名称查找或枚举未授权部门。部门 ID 作为受控引用展示。
- 停用／软删除部门的用户归属不由指标代码猜测；只按现有范围解析结果与用户当前部门 ID 匹配，保留口径说明。
- 筛选只允许关键词（用户名／显示名包含匹配，最多 100 字符）、启用状态、明确部门 ID、创建起止时间和现有“本部门”范围选择。包含匹配按数据库现有排序规则执行，不另设大小写口径。
- 明确部门 ID 和“本部门”均与授权范围取交集。越界部门不能扩大查询范围；无匹配时返回 0，不泄露该部门是否存在。本人没有有效当前部门时，“本部门”请求须澄清。
- 时间字段仅为用户创建时间 `CreatedAt`，不是登录／操作时间。新数据集建议采用起点含、终点不含的区间；只提供一端时为单边条件，不默认过去七天或一个月。两端均提供时要求起点早于终点。
- 时间值要求显式 UTC 偏移，服务端归一为 UTC；相对自然月复用 AIC-003 的显式偏移规则，缺时区必须澄清。首批不推定夏令时地区规则。
- 这是当前用户状态和部门归属的实时查询，即使筛选过去的创建月份，也不代表该月末的历史人员快照。查询时间可返回，未有独立数据水位时明确其缺失，不伪造 `AsOf` 为历史快照时间。
- 不含金额、汇率或舍入；金额规则标为“不适用”。

请求复用现有报表定义 ID，增加明细／指标模式（建议 `Rows`／`Metrics`）。模型只能选择固定指标、维度、筛选与排序枚举，不能提交 SQL、列名、聚合表达式、租户或执行身份。

建议默认明细按用户名、用户 ID 升序；状态分组按状态键；部门分组按人数降序、部门键打破同数并明确空值位置。只提供这些固定排序，拒绝任意字段排序。首批采用展示上限及截断提示，不新增跨页连续快照或无限导出。

明细和分组返回数量沿用现有配置上限。完整匹配总人数为长整数，分组总数、显示组数、显示行数分别表达；不能继续把执行器受限返回行数标为全量 `sourceRowCount`。旧字段保留兼容含义并补明确元数据；工具升级到新契约版本，旧不具备准确总量的结果注明总量未知。

## 4. 服务端授权与数据范围 [Architect]

复用 OpenIddict、原 API 策略、`AiReadOnlyToolRegistry`、`IAiQueryAccessGuard` 和 `IDataScopeResolver`。AI 查询继续要求现有工具查询权限、报表数据集查询权限及 `report:view`；用户数据集另要求 `system:user:view`。范围能力和安全投影由服务器批准目录确定，报表管理员不能通过 ColumnsJson 或 Prompt 修改。

每次执行验证当前用户及租户状态，确认调用上下文与已验证身份一致，检查报表未删除、启用、同租户、数据集已获 AI 批准；不能仅以历史 claims、历史卡片或模型参数作为授权依据。前端查询／导出受影响报表时也必须通过同一 Application 范围用例，防止从其他入口绕开过滤。

新用户数据集范围对应 `user.Id` 与 `user.DepartmentId`：

| 范围结果 | 实际查询语义 |
| --- | --- |
| All | 当前租户非删除用户 |
| CurrentUser | 用户 ID 等于服务端当前身份 |
| CurrentDepartment | 范围解析出的当前部门用户 |
| CurrentDepartmentAndChildren | 范围服务展开的部门集合，不在 SQL 层再推导部门树 |
| CustomDepartments | 范围服务确定的部门集合 |
| 本人与部门合并 | 本人或允许部门，再与租户及业务筛选相交 |
| 无本人、无部门或无法支持的能力 | 空有效范围返回零；不支持该范围能力则拒绝，禁止降级为租户全量 |

执行器只接受 Application 产生的服务端执行上下文，不从 `Params` 读取租户／身份／授权范围。所有值参数化；部门集合使用 SQL Server 可支持的有界集合方式，避免超过参数上限，不能遇到过大集合就丢掉过滤。若执行上限无法覆盖请求，返回明确受控错误。

旧 `system-users`、`system-login-logs`、`system-operation-logs` 及未显式声明范围能力的数据集按 `AllOnly` 处理。AI 保持原局部范围拒绝；建议同步在报表查询／导出服务入口对这些数据集拒绝局部范围用户。这是显式的访问收紧，须随方案确认，不自动将旧视图声明为支持部门范围。

旧含联系方式／IP／失败详情的数据集不因 AI 批准配置就获得新安全字段投影；AI 返回字段必须独立白名单校验，不从视图 `SELECT *` 或可编辑 ColumnsJson 推定安全。首批只为新用户数据集提供模型安全投影；旧数据集缺少安全投影时明确拒绝 AI 返回，普通报表保留其既有字段契约及 AllOnly 限制。

## 5. 分层实现与聚合 [Architect]

1. Application 的报表契约增加范围能力、受控指标定义、有效过滤、数据时间限制、单位、完整总量和截断信息。复用现有数据集目录抽象，静态配置与代码批准指标目录共同校验，不新增通用 SQL 编辑器。
2. `ReportService` 在查询／导出共用入口解析身份、数据集能力、参数及范围，生成内部执行请求并沿用审计。未知筛选、重复大小写键、保留租户参数、类型不匹配、无效时间、非法维度或排序一律拒绝，不静默忽略。
3. Infrastructure 复用独立只读连接、`ReportExecutionGate`、超时、取消及最大行数。固定租户、范围、业务筛选先应用，再在数据库对完整匹配集执行计数及分组，最后限制展示行／组数。
4. 明细用有序读取及额外行检测截断，完整人数单独准确计算；指标计数、组总数和展示组均取自相同有效条件。优先使用单条 SQL 查询避免应用层拼接多次查询结果；不能把截断明细装入内存再聚合。普通读隔离不承诺历史时点快照，响应如实说明实时数据可能变化。
5. AI 保留 `permission.reports.query_dataset` 工具代码和原函数入口，升级 Schema／工具版本，接入已批准新数据集的明细与指标模式；非指标数据集不得假装支持指标模式。
6. 结构化结果新增专用指标载荷和卡片，复用 AIC-003 封套、引用、保留期限和大小限制，旧日志卡片保持其“条”口径。明细复用用户表格，指标卡片显示口径、单位、有效筛选、查询时间、范围说明、完整总量及分组截断。
7. 扩展结果读取和追问白名单，保存实际生效参数、数据集契约版本及范围指纹。引用必须属于同租户、同用户、同会话的真实成功调用；数据集换绑、停用、批准撤销、契约变化或范围变化后隐藏旧敏感卡片并要求重查，不能只检查汇总数量非负。明细重载继续逐行校验当前可见性。
8. 追问只继承已校验筛选；新报表 ID／数据集须发起新查询，不能把旧字段无声带入另一口径。每次追问重新解析当前身份和范围；不把卡片的范围指纹当授权令牌。
9. 前端报表响应只做必要元数据展示，明细查询／导出沿用当前接口与权限；统计模式首批服务于 AI，不新增复杂报表设计器或发布页面。

新结构化结果兼容应按工具／契约版本判断，不能继续把所有工具硬编码为 `1.0`，也不能解除旧结果校验来接入新版本。工具开关仍默认关闭，批准键仍须显式配置；只增加配置说明，不自动打开环境功能或创建租户报表。

## 7. 数据影响与部署策略 [DBA]

结论：**无业务表、实体或 EF 迁移变更；有数据库视图与专用只读角色授权变更。** 不能将本轮笼统记为“无数据库变更”。

建议新增 `reporting.AiSystemUsers`，仅投影用户 ID、TenantId、DepartmentId、UserName、DisplayName、IsEnabled、CreatedAt，源记录显式过滤 `IsDeleted = 0`。TenantId 和范围键仅用于服务端过滤，AI 返回字段由代码白名单控制；不含联系方式、密码、SecurityStamp、角色列表或登录详情。

保留三个旧视图与旧报表定义，不回填或改绑历史记录，不产生发布或业务验收数据。新视图显式授权给既有专用只读角色，不扩大到 schema／dbo 全表读取；脚本中不写凭据。生成独立部署审核脚本及前置对象／列检查，不运行真实数据库脚本。

已有用户索引包含租户／规范化用户名、Email 和 PhoneNumber，不能据此声称部门与时间查询已经优化。先在隔离 SQL Server 验证实际查询计划、读取量、部门集合规模和超时；是否新增 `(TenantId, DepartmentId, CreatedAt)` 等索引由测量决定。若需要索引迁移、表结构或新的快照隔离配置，重新提交 DBA 方案确认，不在本轮自动执行。

新增视图仅当前值读取，不引入历史用户状态表或持久化指标目录；指标与范围元数据复用批准数据集配置及代码目录。结果／上下文复用 `AiMessage.Content`，继续受 64 KiB 封套、4 KiB 上下文、256 KiB 读取总量与保留期限约束，越界裁剪仅减少展示，不改变完整指标值。

发布顺序：管理员审核并在批准环境创建视图／授权，配置只读连接与显式批准键，按现有报表管理入口创建指向新数据集的定义，再执行目标身份验收后开启 AI 工具。缺视图、字段、角色授权或批准配置时拒绝，不退回业务库连接或旧无范围视图。

回退先关闭新工具／撤销批准键、停止后续新查询，再回退兼容应用配置。新增视图可以保留，默认不执行删除、EF Down 或数据清理；历史结果不重新解释为另一版本口径。视图部署与真实库权限修改另行取得明确执行授权。

## 9. 测试与退出条件 [Reviewer]

确定性测试：

- 指标总量／启用／停用与同条件可信查询一致，零数据返回 0；空部门独立分组，用户多角色不重复统计。
- All、本人、本部门及下级、自定义部门、本人并部门、用户覆盖、无角色默认本人、空范围与失效身份；SQL 返回集合与既有 DataPermissionFilter 基准一致。
- 同 ID 跨租户、越界部门过滤、跨租户报表与模型租户参数均不能获得数据；未批准、安全投影缺失与不支持范围拒绝。
- 参数组合、未知／重复键、类型错误、明确偏移、边界时刻、半开区间、空时间端点、当前状态非历史快照说明。
- 数据超过明细／分组展示上限时，完整指标不受截断影响；稳定排序、同人数并列、空分组、长整数计数及大部门集合限制。
- 新结果写入／重载、合法追问、错误引用、权限／范围变化、数据集撤批／换绑／版本变化、封套裁剪与旧版本兼容；历史文字不作为指标事实来源。
- 新用户字段白名单不受报表 ColumnsJson 或 Prompt 控制，不包含联系方式、IP、凭据或原始日志；取消、超时与失败审计继续有效。
- Query、Export 与 AI 三入口应用相同范围；旧 AllOnly 数据集的访问收紧有明确回归测试和说明。
- AIC-005 既有场景工具绑定、不可变版本、构建兼容与门槛不被放宽。

验证计划：后端相关构建、单元与现有回归；HTTP 授权／契约测试；前端相关单测、类型检查、lint、build；离线合成评测与差异检查。数据库测试只在明确隔离环境运行，记录实际通过与跳过，不以 InMemory 或 SQL 文本断言证明真实 SQL Server 聚合／计划／权限通过。

环境验收需要 Owner 确认口径、明确身份范围夹具、超出截断规模的数据、只读数据库角色与查询计划、真实供应商 Tool Calling、卡片／追问／报表导出体验。尚无目标数据量与延迟 SLA，不虚构性能通过阈值；至少记录实际规模、耗时、读取量、计划及现有限流／超时是否生效，再由验收人决定是否达标。

退出条件：同口径业务核对通过，局部范围不泄露数据、不支持能力明确拒绝，聚合不依赖截断样本，必要环境与人工验收具备证据。仅本地代码和确定性测试完成时标“待验收”，不标“已完成”。

方案阶段复核：代码和架构依据已核对，当时未运行构建或功能测试。用户确认后的实现、独立复核与实际验证结果见验收记录，不引用 AIC-002～005 的历史通过结果作为本轮验证。
