## 1. 目标与边界 [Architect]

### 1.1 建设目标

1. 优先解决权限平台的真实问题：权限排障、审计分析和受控查询。
2. 让回答有证据、查询有口径、连续追问可复现。
3. 建立模型、提示词、工具变更的评测与发布闭环。
4. 在真实业务规则明确后，逐步接入 ERP／WMS，只读先行、写入后置。
5. 改善长任务可靠性、断线恢复与使用体验，继续复用现有平台设施。

### 1.2 本计划不直接授权的事项

- 不实施业务代码、不执行数据库迁移、不发布到生产环境。
- 不自动创建新权限体系、替换认证方案或引入大型 Agent 框架。
- 不允许模型执行任意 SQL、自行授权、自行审批或绕过人工确认写入业务。
- 不推定 ERP／WMS 的字段、统计口径、组织／仓库／账套范围及接口契约。
- 不自动 commit、push；后续如需操作，遵循用户明确指令。

验收：与同口径的可信业务查询结果一致；局部范围用户只看到授权范围；不支持的口径明确拒绝或澄清。

### AIC-007：首个真实业务只读数据集

对应既有 P4-B2；若查询外部系统，同时涉及 P5-C。库存、订单进度等只是候选，不视为已经选定的业务。

| 信息 | 要求 |

| 查询口径 | 字段含义、聚合规则、时间边界、单位及数据时效 |
| 授权映射 | 租户、组织、仓库、账套和外部服务身份范围；不适用的维度明确注明 |

实施步骤：

- [ ] 复用 Application 处理器；内部调用不绕行自身 MCP HTTP 服务。
- [ ] 按需要暴露 AI 工具或 MCP 数据集；外部公开不是内部工具上线的必选项。
- [ ] 更新 Schema／Hash、字段授权和发布状态；新增字段不自动开放。
- [ ] 对缺失服务数据范围采取拒绝策略。
- [ ] 在目标环境验证身份、字段授权、审计、限流、超时及业务结果一致性。

验收：业务 Owner 签认查询口径；目标调用者端到端验证通过；未批准字段、租户和范围均不可访问。

### AIC-008：持久化后台运行与断线恢复

- [ ] 盘点现有 Run 状态、租约、心跳、watchdog、取消和预算结算，避免新增第二套状态机制。
- [ ] 设计异步提交契约：返回运行 ID／接受状态，保留前端兼容策略。
- [ ] 在现有后台设施中选择合适实现，保证 Run 创建与任务投递的可靠衔接。
- [ ] 后台保存必要身份引用，不保存用户 Bearer Token；执行时重建租户上下文并检查身份、会话及权限有效性。
- [ ] 明确执行中撤权／停用的检查点，尤其在每次工具与写操作前重新检查。
- [ ] 定义重复投递、租约抢占、进程重启、取消竞态和终态更新规则。
- [ ] 外部模型调用可能重复计费；业务动作必须幂等。对结果不明的调用不进行无条件重试。
- [ ] 对预算预留、扣减、超时回收和重试结算做一致性测试。
- [ ] 前端通过现有实时通道接收进度，断线后按 Run 查询恢复，实时消息去重且隔离用户／租户。
- [ ] 可靠性验收通过后，再按需要增加答案流式输出；不输出内部推理、原始敏感工具结果或未校验参数。

数据库：优先复用现有 Run 字段；缺少的投递、恢复或版本字段采用兼容扩展，并评审索引及保留策略。

验收：刷新页面不丢失运行状态；进程重启可恢复或明确终止；重复任务不导致重复业务写入或错误结算；取消与超时能进入一致终态。

第二阶段退出条件：一个真实只读场景通过业务验收；后台执行完成适用的故障恢复测试；若开放外部 MCP，AIC-001 对应验收已完成。

### AIC-009：动作权限解耦及真实单据草稿

- [ ] 测试确认后数据变化、重复确认、权限撤销、跨租户、执行超时和后台重试。

验收：不同动作不能共用错误的 Demo 权限；失败不产生半完成业务结果；AI 不能绕过确认或现有业务校验。

### AIC-010：有权限边界的文档知识库

- [ ] 确认资料范围、Owner、使用许可、更新周期、访问控制和删除要求。
- [ ] 先验证文档质量与检索价值，再选择检索存储和必要依赖，不能先默认引入向量数据库。
- [ ] 建立导入、解析、版本、索引更新和删除传播流程；处理扫描失败、重复文件及过期资料。
- [ ] 检索前按租户和文档权限过滤；撤权／删除后禁止继续命中，包括缓存。
- [ ] 回答提供引用与版本，无可靠依据时明确说明；文档中的指令仅视为资料内容。
- [ ] 实时业务事实继续通过受控工具获取，不能把旧文档当作实时库存或订单状态。

验收：引用可核验，过期和无权文档不进入模型；跨租户检索为零泄露；权限变更与索引失效机制可测试。

数据库：可能涉及资料元数据、索引引用和任务记录；索引基础设施、容量及清理策略在独立方案中确认。

### AIC-011：规则驱动的异常提醒

- [ ] 确认异常规则、执行频率、接收人、通知渠道、去重窗口和关闭条件。
- [ ] 使用已有调度设施执行确定性查询／规则，AI 仅生成辅助解释和摘要。
- [ ] 执行时重新检查任务身份与范围；发送前检查接收人可见范围，不能向所有人广播敏感明细。
- [ ] 复用现有通知，支持幂等、暂停、失败记录、费用限制及必要的人工处理入口。
- [ ] 测试重复调度、无异常、规则失效、接收人撤权、供应商不可用及通知失败。

验收：同一异常不会无限重复通知；无异常不消耗不必要的模型调用；模型故障不影响确定性异常结果的记录。

数据库：优先复用调度和通知能力，仅补必要规则配置和去重状态。
