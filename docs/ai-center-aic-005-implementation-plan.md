## 2. 首批范围与管理员边界 [Architect]

首批新增一个受控场景 `permission-assistant`，面向已落地的权限排障、对象查找和连续追问。允许绑定已有工具：

- `permission.diagnose`
- `permission.users.search`
- `permission.departments.search`
- `permission.roles.summary`

场景初始绑定以上四个工具；管理员可以选取其子集。案例执行范围不能随工具减少而静默缩减，导致必需案例失败时不允许发布。场景配置本身不授予任何工具权限、代查权限或数据范围。

审计助手暂不进入本轮可发布场景：AIC-004 没有覆盖其日志口径的专用黄金案例，不能直接复用权限排障通过率证明审计助手通过。场景服务保留扩展点，后续新增场景需同时提供代码允许的工具目录和相应评测集。

管理员可以编辑：场景展示名／说明、补充 Prompt、允许工具子集、运行限制、temperature 和最大输出 Token。模型采样参数沿用现有校验：temperature 为 0～2，输出 Token 为 1～128000；预算和供应商资格仍逐次检查。运行限制不得超过现有 6 轮／10 次工具／20 条历史／90 秒上限，快照工具总数不得超过网关的 32 个限制。

管理员不能编辑：代码安全提示、租户或调用者身份、授权矩阵、数据范围规则、工具实现、Schema、RequiredPermissions、结果封套、安全阈值、评测案例预期或代码构建身份。补充 Prompt 限长并作为独立场景指令加入；发布快照同时包含代码安全提示及其摘要。安全和业务校验始终由后端实施，不能依赖提示词文本实现。

现有固定平台助手保留为明确标记的代码内置兼容入口，继续提供既有查询和 Demo 草稿能力；不允许通过配置把它变为可编辑场景，也不接入本轮新动作。未传场景的旧客户端继续使用该入口。新权限助手须通过正常发布门槛后才可选择；发布失败或停用时不能自动切回内置入口。

## 3. 不可变快照与代码兼容 [Architect]

以一次冻结产生一个不可变版本，不在原版本上修改 Prompt、绑定或参数。修改通过复制为新草稿后重新冻结、评测和发布完成。

快照保存：

1. 契约版本、租户、场景编码、版本序号、草稿修订摘要。
2. 安全提示版本与内容摘要、场景补充提示、合成的实际系统提示内容／摘要。
3. 工具代码、函数名、实现声明版本、描述、原始与模型实际输入 Schema、输出 Schema、RequiredPermissions、数据分类／范围政策、超时及行数约束。
4. 关键运行限制、temperature、最大输出 Token，以及结构化结果／追问契约版本。
5. 实际构建身份及工具／编排兼容摘要。构建身份由构建产物提供，不接受管理员或模型填写；Git 提交与源码摘要作为辅助证据，不能仅使用 HEAD 或数据库版本号。
6. 稳定排序和明确序列化规则计算的 SHA-256 内容摘要。

首次采用严格兼容：冻结、评测、发布、继续运行和回退时均校验当前构建身份及实际工具契约，不声明跨代码构建自动兼容。工具不存在、实现版本／Schema／安全策略或构建身份变化时拒绝运行，要求重新冻结和评测。构建身份缺失时受控失败，不能使用测试身份或任意字符串作为生产默认值。

数据库快照保存配置，不能恢复旧程序集或旧工具实现；历史版本展示要明确这一限制。发布内容写入后由领域／应用状态规则及 Infrastructure 保存检查共同禁止更新和删除；允许变化的资格／生命周期记录独立保存。此约束针对应用持久化链路，不宣称可防止数据库管理员直接修改数据。

## 4. 草稿、评测、发布与回退 [Architect]

流程为：编辑草稿 → 冻结候选版本 → 导出评测输入 → 隔离评测 → 导入证据 → 人工事实审核 → 发布并切换当前版本。

- 草稿修改必须提供并发令牌；冻结时校验允许工具、运行参数及构建。已冻结内容不可再编辑。
- 评测沿用 AIC-004 的独立进程和合成 InMemory，不在 API 请求内调用付费模型，也不读取业务数据；本轮交付显式真实模型入口，实际付费运行须另行明确供应商、网络条件和预算。
- 扩展 AIC-004 评测工具，使其在隔离编排中执行指定候选快照，并记录实际 Prompt、按夹具授权后的工具目录、实际参数、构建身份和模型配置指纹。不能只给旧报告加一个候选版本 ID。
- 评测证据绑定候选内容哈希、案例集／预期／检查器摘要、报告哈希、执行模式、模型配置指纹和构建身份。仅有哈希相同不能证明报告真实，报告导入是授权治理管理员提交的审计证据，必须注明这一信任边界。
- 后端严格解析报告并根据随构建固定的案例预期、实际观测和检查规则重新计算确定性判定，不接受客户端的 `Passed`、汇总正确率或门槛结论。限制文件大小、深度、案例数量和重复项；原始文件按现有 32 MiB 上限处理，仅存脱敏必要证据和受控摘要。
- 人工审核通过平台认证操作完成，审核者和时间由服务器记录；不把上传 JSON 中的 Reviewer 当作已认证审核者。审核绑定精确报告和案例版本，不自动批准模板或模型自评分。首批复用治理管理权限，不引入未经确认的双人审批规则。
- 抽取 AIC-004 中必需的纯评测契约、判定及门槛到 Application 的独立目录，CLI 和生产服务共同使用。测试夹具、文件／进程 I/O、供应商调用和控制台仍留在工具工程；Api／Application 不引用 `PermissionSystem.AiEvaluations` 或具体 Infrastructure。

正常发布同时要求：离线检查全部通过；黄金案例与事实人工审核完成；真实模型工具／参数、事实正确率分别至少 95%；安全案例全部通过；无预算终止、裁剪导致不可审阅或缺失案例；相对已审核且可比基线无新增退步。首次发布没有历史基线时，必须显式完成人工首版基线确认，不伪造对比通过。

发布资格按模型配置组合记录。继续复用既有 Agent 路由：主、灰度、备用中可能被选中的每个组合均须具备与该版本绑定的真实模型证据；不能只评测主模型后开放未经评测的备用模型。模型、采样或协议配置变化导致指纹不匹配时阻止执行并提示重新评测；供应商停用、合规撤销、地址安全、预算和租户限制仍按当前状态检查。凭据不进入快照或报告，正常密钥轮换不作为模型能力变化处理。

发布、停用、撤销资格和回退均走幂等写接口、乐观并发和事务，记录操作者、理由、前后版本及证据引用。失败事务不得切换当前指针。回退仅能切换到同租户、同场景、仍有效且与当前代码／模型兼容的已发布版本，不新建平行灰度算法，不提供跳过评测的正常发布开关。

## 5. 会话固定版本与运行追溯 [Architect]

- 新建受控场景会话时固定到当时当前已发布版本，后续发布不静默改变该会话。
- 每次发送及重试重新检查版本资格、代码兼容、当前身份／租户、供应商、工具权限和预算；重试固定到原版本，不以最新版本偷偷替换失败 Run。
- 会话版本停用或不兼容时保留历史阅读，阻止新 Run。升级通过用户明确选择创建新会话完成，显示目标版本；首批不迁移旧消息或自动继承旧 contextRef。
- 发布指针切换不终止已开始运行；停用／撤销在开始 Run、每轮模型调用和每次工具执行前检查。已在途的外部请求不能承诺瞬间撤回，后续步骤及结果持久化／返回前再次检查资格并受控结束。
- Run 保存版本 ID／内容哈希、执行构建身份和脱敏执行配置，包括实际系统提示摘要、实际提供工具契约、运行限制、每次使用的供应商／模型与采样配置指纹。权限变化造成的工具子集、追问导致的单工具缩减必须反映在实际配置中。
- 旧会话／Run 的版本关联保持 NULL，展示“历史配置追溯不完整”。旧会话继续使用代码内置兼容入口；升级只能新建受控场景会话。
- 本轮之后的内置兼容 Run 也保存实际配置及构建身份，标明 `BuiltinCompatibility`；不把其记录冒充经 AIC-005 门槛发布的版本。迁移前旧 Run 不补写今天的配置。

## 6. 数据影响、迁移及并发 [DBA]

结论：**有数据库结构变更**，不能按“无数据库变更”处理。建议新增以下实体，全部继承 `BaseEntity`，沿用租户、创建／更新审计、软删除和 SQL Server RowVersion。

| 建议实体／表 | 职责与约束 |
| --- | --- |
| `AiScenario`／`ai_scenario` | 租户场景、启停及当前版本指针；唯一 `(TenantId, Code)`，复用软删除索引惯例 |
| `AiScenarioDraft`／`ai_scenario_draft` | 可编辑 Prompt、工具代码子集、参数与修订；使用 RowVersion 防止覆盖 |
| `AiScenarioVersion`／`ai_scenario_version` | 不可变快照 JSON、哈希、序号、构建身份；唯一 `(TenantId, ScenarioId, VersionNumber)`，建立场景／哈希查询索引 |
| `AiScenarioEvaluation`／`ai_scenario_evaluation` | 不可变脱敏证据、报告／预期哈希、模式、模型指纹及服务端判定 |
| `AiScenarioReleaseEvent`／`ai_scenario_release_event` | 追加发布／停用／回退／人工审核／资格撤销事实、理由和证据关联；按租户、场景、版本及时间建立索引 |

工具绑定保存在版本快照内，首批不另建冗余可编辑 Schema 表；评测与发布记录不复制原始业务消息、密钥、端点或日志正文。当前有效资格通过追加事实和场景指针判断，生命周期变更不修改快照内容。

为 `AiConversation` 增加可空 `ScenarioId`／`ScenarioVersionId`；为 `AiRun` 增加可空版本关联、内容哈希、构建身份和执行配置 JSON／摘要。旧字段保留。JSON 使用有界 `nvarchar(max)`，Application 写入前校验字节数；场景快照和执行配置建议各最多 256 KiB，导入报告总上限不等于单行存储大小。

关联使用 Restrict，避免级联删除历史；新关联须约束租户一致性，不能只靠单列外键或全局过滤推定安全。使用包含 TenantId 的关系约束，迁移时评审所需复合唯一键；Application 同时显式校验场景、版本、证据与会话归属。发布事务内校验版本资格、构建和场景 RowVersion，并更新场景指针、追加事实；版本序号有唯一约束兜底，竞争冲突返回受控错误，不覆盖赢家。

迁移仅新增表、可空字段、约束和索引，不回填旧 Run 的不存在配置，不自动发布权限助手，不修改既有模型路由、预算、权限或 Demo 数据。场景初始化使用代码允许目录及租户显式管理流程，不在历史迁移里循环产生“已通过”版本。

实现阶段生成 EF 迁移及供审核的 SQL 脚本，检查大表 ALTER／索引锁风险和已有数据兼容。此方案确认不等于授权操作实际数据库；本轮不自动执行业务数据库迁移、备份、恢复或部署。SQL Server 事务／并发验收需要独立隔离环境。回滚优先回退应用并保留新增数据；Down 会删除新发布历史，不作为自动回退步骤。

## 7. 预计文件与实施顺序 [Developer]

以下新增文件名为拟定名称，不表示已存在；实现沿用项目风格，范围变化涉及架构或数据设计时重新确认。

1. Domain：新增场景、草稿、不可变版本、评测证据、发布事实及状态规则；修改 `Entities/AiConversation.cs`、`Entities/AiRun.cs`，保持 Domain 不依赖 EF／HTTP。
2. Application：新增 `AiCenter/AiScenarioModels.cs`、`AiScenarioService.cs`、快照构建／校验和发布门槛服务；最小提取 `AiConversationService` 的 Prompt／参数生成与版本解析；增加评测纯契约及构建身份接口。继续复用现有注册器、追问、路由、预算、准入、取消和审计。
3. Infrastructure：新增实体映射、构建身份实现、不可变保存检查、迁移及 SQL 脚本；修改 `Data/AppDbContext.cs` 和相关 DI，不承载发布业务流程。
4. Api：新增 `Controllers/AiScenarioController.cs`；仅协议与入口，沿用 `ApiResult`、Permission、IdempotencyKey、CancellationToken。查看复用 `ai:governance:view`，管理／审核／发布复用 `ai:governance:manage`；聊天场景选择仍要求现有聊天访问及当前租户许可。
5. 评测：修改 `PermissionSystem.AiEvaluations`、`scripts/aic-004-evaluate.ps1`、必要案例清单及 CI，支持冻结版本输入与绑定报告；保留旧离线入口和报告读取兼容，旧报告缺少发布绑定时明确不可用于新版本发布。
6. 前端：修改 `src/api/ai.ts`、`views/ai/governance/index.vue` 并拆出必要场景治理组件，增加草稿、冻结、证据导入／人工审核、发布、历史、停用／回退交互；修改 `AiChatDialog.vue`，支持新会话场景选择、版本标签和受控升级为新会话。复用现有页面路由及权限状态，不新增认证体系或菜单权限种子。
7. 测试与文档：增加 Domain／Application／映射／API／SQL Server 并发及 Vue 回归；新增 AIC-005 验收记录，同步本方案、后续计划和 `ai-center-mcp-implementation-plan.md`，按证据保留待验收状态。

## 8. 验证与风险 [Reviewer]

必须验证：

- 已冻结快照通过业务服务及直接 EF 保存均不可改写／删除；复制新草稿不会影响旧版本。哈希排序、Unicode、Schema 扩展与实际模型请求一致。
- 越权管理、跨租户引用、调用者停用、撤权后的旧上下文、未绑定工具、伪造身份和恶意补充 Prompt 均不能改变原授权／数据范围／服务端结论。
- 失败或未审核报告、离线冒充真实模型、旧报告、构建／模型／参数不匹配、缺失安全变体、伪造 Passed、重复案例、裁剪报告和退步均阻止发布；首版基线必须显式审核。
- 主／灰度／备用资格逐个校验；供应商变更不能悄悄沿用旧资格；模型路由继续按既有稳定算法执行。
- 会话固定版本、重试固定版本、升级新建会话、旧客户端／旧 Run 可读、停用后的持续检查、代码不兼容回退拒绝。
- 发布／回退／草稿保存并发冲突、重复幂等请求、事务回滚、版本序号唯一约束和跨租户外键；InMemory 不能代替 SQL Server 验证。
