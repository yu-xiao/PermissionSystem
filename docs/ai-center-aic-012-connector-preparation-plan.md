## 1. 现状与首批建议 [Architect]

方向 1 的启动条件是至少一个稳定的真实外部查询需求。目前仓库资料没有确定首批目标系统、Owner、正式查询契约或身份映射。接入准备方案已确认，下一步填写第 2 节真实契约，再提交具体实现方案。

首个实现批次限于一个系统、一个经批准的只读查询和一种已确认协议。内部 AI 使用与对外公开必须分别确认；只读不能仅靠 REST 方法名或 MCP 工具注解推定，须由目标系统 Owner 确认接口业务效果和最小读取权限。暂不建设通用连接器平台，也不加入外部写入、任意 URL 查询或自动工具发现后启用。

## 3. 契约确定后的实现边界 [Architect]

以下为设计约束，具体 DTO、权限码、配置、超时／限流数值与新增文件名在真实契约确定后提交确认。

1. Application 在现有 `AiTools/` 中实现一个受控 handler 和目标查询接口，负责逐次调用授权、活动租户与调用者数据范围、服务端身份映射、白名单投影及结果引用。外部返回前复核授权；缺失／冲突／停用映射拒绝，不回退到默认账套。
2. Infrastructure 实现该唯一协议适配及 DI，负责固定目标、受保护凭据解析、出站校验、取消／总截止时间、有界响应读取和契约验证。目标 URL、响应链接、MCP 元数据及外部文本不成为新的外联授权或工具指令。
3. 使用既有工具结果／引用表达来源、查询时间、数据时效、行数和截断。无数据、无权、超时、协议异常与来源不可用保持可区分；异常不暴露凭据、原始响应或敏感请求参数。
4. 工具须显式纳入获准场景及工具白名单，沿用 AIC-003／004／005 的结构化契约、评测和版本发布。注册成功不代表自动公开或自动获得发布资格。
5. 优先使用既有权限和审计抽象；缺少适用业务权限、映射存储或出站审计能力时，单独提出方案，不借用入站凭据／日志表或宽泛管理权限。

预计影响现有 Application 的 `AiTools/`、相关场景／接口与 DI，Infrastructure 的单一外部协议适配／配置与 DI，以及 UnitTests／IntegrationTests 的 `AiCenter/`。API、前端、权限种子和持久化是否需要改动由正式契约决定；当前不预定新页面、管理接口、实体或 SDK 依赖。
