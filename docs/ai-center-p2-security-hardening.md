# AI 中心 P2 安全调整

## 日志正文

`/api/ai` 与 `/api/v1/ai` 下的请求不再读取请求正文或捕获响应正文用于通用操作日志，包括失败请求。操作人、租户、请求路径、状态、耗时、TraceId 等原有审计元数据继续保存。其他业务接口沿用原有日志脱敏规则。

本次调整只影响新请求；已保存或归档的日志正文不会自动清理。

## 用量和预算

每次模型调用前保存 `EstimatedInputTokens` 和 `EstimatedOutputTokens`，与供应商返回的 `InputTokens`、`OutputTokens` 分开。输入沿用现有字符数估算，输出使用实际请求的最大输出 token 数。估算不是供应商账单的精确值。

结算优先使用有效的真实用量，缺失的部分使用调用前估算。超时、失败及进程退出后回收的调用同样保守计入费用和小时 token 配额，真实用量字段不被估算覆盖。未配置价格时仍保存 token 估算，但不虚构货币费用。

未结算的预算预占不因到期而从统计中消失。后台回收将费用预占转为估算费用，并与 Run 失败状态一起保存。重复结算不累加费用；若随后提供真实用量，再次结算会替换原估算。此改动不新增供应商账单自动对账任务。

未配置 `MaxTokens` 时统一使用 4096；已配置时使用配置值。每轮调用和备用供应商均使用相同的有效上限进行预算预占和模型请求。

## 数据库和部署

迁移 `20260924032728_AddAiUsageEstimates` 仅为 `ai_usage_log` 增加两个可空 int 字段，不回填历史真实用量、不删除数据。历史记录若缺少估算依据，不能准确追溯补算。

应先应用迁移，再运行新版 API 和 Worker。两者应一起更新，旧版本不会保存估算用量，且旧 Worker 仍可能释放未知费用。开发环境 API 启动沿用项目原有自动迁移行为。本次代码验证没有向实际数据库应用迁移。

回退应用时可保留新增的可空列。迁移 Down 会删除估算列及其中数据，应先评估备份和预算统计影响，不应自动执行。
