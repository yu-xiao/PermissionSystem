# PermissionSystem 使用与测试文档

本文档用于对当前 PermissionSystem 系统做人工功能测试和联调验证。内容依据现有后端控制器、前端页面、API 包装层、种子数据和已有验收文档整理，重点说明“从页面怎么操作、测试时看什么结果”。

## 1. 测试前准备

### 1.1 本地启动

后端默认本地地址：

- HTTP：`http://localhost:5264`
- HTTPS：`https://localhost:7281`
- Swagger：`http://localhost:5264/swagger`
- Hangfire Dashboard：`http://localhost:5264/hangfire`
- 健康检查：`http://localhost:5264/health`
- 健康详情：`http://localhost:5264/health/detail`

前端默认本地地址：

- Vite：`http://localhost:5173`
- Docker 前端：`http://localhost:8080`

本地运行前确认以下配置已在本机安全位置配置好，不要提交真实值：

- `ConnectionStrings:DefaultConnection`
- `SeedData:AdminPassword`
- `SeedData:OAuthClientSecret`
- `Security:SystemConfigEncryptionKey`

开发环境启动 API 时会自动执行 EF Core migration 和 SeedData。默认管理员用户名为 `admin`，密码使用本地配置中的 `SeedData:AdminPassword`。

### 1.2 Docker 启动

从根目录复制 `.env.example` 为 `.env`，填写本机测试值后执行：

```powershell
docker compose up -d
```

默认服务：

- 前端：`http://localhost:8080`
- 后端 API：`http://localhost:5000`
- SQL Server：`localhost,1433`
- Redis：`localhost:6379`

RabbitMQ 默认不启用。如需测试消息队列和 Outbox 发布，使用 `mq` profile 并开启对应环境变量。

### 1.3 常用测试账号与权限

- `admin` 是种子数据内置管理员，拥有 `SuperAdmin` 角色和全部菜单/权限。
- 普通用户需要在“系统管理 / 用户管理”中新建，并分配角色。
- 角色权限调整后，普通用户通常需要重新登录，Token 中的权限声明才会刷新。
- 测试无权限场景时，建议创建一个只拥有少量菜单和按钮权限的角色。

## 2. 通用界面使用

### 2.1 登录与退出

入口：`/login`

操作：

1. 输入用户名、密码登录。
2. 登录成功后进入首页。
3. 右上角用户下拉菜单可进入“个人中心”、修改密码、退出登录。
4. 修改密码成功后，前端会清理登录状态并跳回登录页。
5. “退出所有设备”会吊销所有会话并要求重新登录。

测试重点：

- 未登录访问后台路由应跳转登录页。
- 登录成功后应加载动态菜单、权限码和通知状态。
- 退出登录后应清理 token、动态菜单、页签和通知连接状态。

### 2.2 后台布局

后台包含左侧菜单、顶部栏、面包屑、页签和内容区。

常用操作：

- 左侧菜单进入功能页面。
- 顶部可折叠菜单、切换主题、全屏、查看通知。
- 页签支持刷新当前页、关闭当前页、关闭其他页、关闭左侧/右侧页、关闭全部。
- 首页页签固定，不可关闭。

测试重点：

- 菜单由当前用户权限动态生成。
- 无菜单权限时不应显示对应菜单。
- 无页面权限时访问路由应进入 403。
- 页面刷新后，已登录状态下应能恢复当前用户信息。

### 2.3 列表页通用操作

大部分管理页遵循统一模式：

- 顶部搜索表单。
- 表格列表。
- 分页。
- 新增/编辑弹窗。
- 行操作按钮。
- 表格工具栏刷新、密度、列设置等操作。

测试时建议每个页面至少覆盖：

1. 搜索条件查询。
2. 分页切换。
3. 新增一条数据。
4. 编辑刚新增的数据。
5. 启用/禁用或删除。
6. 使用无权限用户确认按钮不可见或接口返回 403。

## 3. 系统管理

### 3.1 租户管理

入口：系统管理 / 租户管理

用途：维护租户编码、名称、状态和基础信息。

操作：

1. 使用关键字查询租户。
2. 新增租户，填写租户编码、名称、描述和启用状态。
3. 编辑租户基础信息。
4. 启用或禁用租户。

测试重点：

- 租户编码应唯一。
- 禁用租户后，相关登录和业务访问策略应按后端规则生效。
- 多租户接口测试可使用 `X-Tenant-Id` Header 验证数据隔离。

### 3.2 部门管理

入口：系统管理 / 部门管理

用途：维护部门树，供用户归属、数据权限和业务字段使用。

操作：

1. 查看部门树。
2. 新增根部门或子部门。
3. 编辑部门名称、排序、状态。
4. 启用/禁用部门。
5. 删除无子节点、无关联业务限制的部门。

测试重点：

- 部门树层级和排序显示正确。
- 删除父级部门前应确认是否存在子部门或用户引用。
- 数据权限测试时，需要先准备多层级部门。

### 3.3 用户管理

入口：系统管理 / 用户管理

用途：维护系统用户、账号状态、角色分配、导入导出。

操作：

1. 按用户名、昵称、状态等条件查询。
2. 新增用户，填写用户名、显示名、部门、邮箱、手机号、密码和启用状态。
3. 编辑用户基础信息。
4. 启用或禁用用户。
5. 重置用户密码。
6. 点击“角色”为用户分配角色。
7. 点击“导出”导出当前查询条件下的用户列表。
8. 点击“模板”下载导入模板。
9. 点击“导入”上传 Excel，查看导入成功和失败行。

测试重点：

- 用户名应唯一。
- 禁用用户不应继续正常登录。
- `admin` 内置账号有保护逻辑，不能被删除、禁用或破坏关键角色关系。
- 给普通用户分配权限后，需要重新登录普通用户验证菜单和按钮变化。
- 导入测试应覆盖重复用户名、缺少必填列、格式错误等失败行。

### 3.4 角色管理

入口：系统管理 / 角色管理

用途：维护角色、菜单权限、按钮/API 权限、数据范围和角色用户。

操作：

1. 新增角色，填写编码、名称、排序和状态。
2. 编辑角色基础信息。
3. 点击“分配权限”打开权限矩阵。
4. 在矩阵中按模块选择菜单和动作权限。
5. 点击“数据范围”设置角色的数据权限。
6. 点击“关联用户”为角色选择用户。
7. 删除不再使用的普通角色。

数据范围支持：

- 全部数据。
- 本人数据。
- 本部门数据。
- 本部门及下级数据。
- 自定义部门。

测试重点：

- 选择动作权限时，应自动勾选对应菜单和基础查看权限。
- 保存权限后，普通用户重新登录才会拿到最新权限声明。
- 自定义部门范围应能选择部门树节点。
- `SuperAdmin` 内置角色受保护，不能被删除或破坏。
- 普通管理员不应能把自己或他人提升为 `SuperAdmin`。

### 3.5 菜单管理

入口：系统管理 / 菜单管理

用途：维护动态菜单树、路由路径、组件路径、图标、排序和菜单权限码。

操作：

1. 查看菜单树。
2. 新增目录或页面菜单。
3. 编辑菜单名称、路径、组件、重定向、图标、排序、显示状态、权限码。
4. 删除不再使用的菜单。

测试重点：

- 菜单路径和组件路径必须与前端页面匹配。
- 菜单权限码应与角色权限分配联动。
- 删除菜单后，分配该菜单的角色不应继续看到入口。

### 3.6 权限管理

入口：系统管理 / 权限管理

用途：维护按钮/API 权限码，供 `PermissionAttribute`、`v-permission` 和角色授权使用。

操作：

1. 按模块、动作、关键字查询权限。
2. 新增权限码，填写权限编码、名称、模块和动作。
3. 编辑权限说明。
4. 删除未使用的权限。

测试重点：

- 权限码应与后端控制器上的权限声明一致。
- 删除或改名权限码会影响菜单按钮和接口授权，需谨慎测试。

### 3.7 字典管理

入口：系统管理 / 字典管理

用途：维护通用枚举数据，例如状态、性别等。

操作：

1. 新增字典类型，填写编码、名称、描述、状态和排序。
2. 在某个字典类型下新增字典项，填写标签、值、颜色、样式、默认值、状态和排序。
3. 编辑或删除字典类型/字典项。

测试重点：

- 字典类型编码应唯一。
- 启用字典项接口只返回可用项。
- 删除字典类型前应确认是否还有业务引用。

### 3.8 参数配置

入口：系统管理 / 参数配置

用途：维护系统配置项，支持按分组查询和读取配置值。

操作：

1. 按分组、关键字查询配置。
2. 新增配置项，填写配置键、配置值、分组、描述、是否敏感等信息。
3. 编辑配置项。
4. 删除配置项。

测试重点：

- 敏感配置不应在列表中明文泄露。
- 需要查看敏感值时，应走后端敏感操作校验逻辑。
- 配置更新后应确认缓存刷新是否生效。

### 3.9 文件管理

入口：系统管理 / 文件管理

用途：上传、下载、查询和删除文件资源。

操作：

1. 上传允许扩展名内的文件。
2. 按文件名、业务类型、业务 ID 查询。
3. 下载文件。
4. 删除文件。

默认允许扩展名包括图片、PDF、Office 文档、文本、CSV、压缩包等。默认最大文件大小为 20 MB。

测试重点：

- 超大文件应被拒绝。
- `.exe`、脚本文件、路径穿越文件名应被拒绝。
- 下载文件内容应与上传文件一致。
- 本地存储模式下确认 `uploads` 目录可写。

### 3.10 健康检查

入口：系统管理 / 健康检查

用途：查看 API、SQL Server、Redis、RabbitMQ、Hangfire、磁盘存储等组件状态。

操作：

1. 打开页面查看整体状态。
2. 查看每个组件的状态、耗时、说明和数据。
3. 分别在启用/关闭 Redis、RabbitMQ 的配置下验证状态变化。

测试重点：

- 未启用 RabbitMQ 时，不应因为 RabbitMQ 不存在而整体失败。
- 启用 Redis/RabbitMQ 后，如果组件不可用，应显示 unhealthy。

### 3.11 任务管理与定时任务

入口：

- 系统管理 / 任务管理
- 系统管理 / 定时任务
- `/hangfire`

用途：

- “任务管理”查看后端注册的 Job 和执行日志，可手动触发、启用、禁用。
- “定时任务”维护可配置任务，支持触发执行和查看任务日志。
- Hangfire Dashboard 用于底层任务队列和执行状态观察。

操作：

1. 查询任务列表。
2. 手动触发 Demo 任务。
3. 查看执行日志。
4. 启用或禁用任务。
5. 访问 `/hangfire` 查看 Dashboard。

测试重点：

- Worker 未启动时，任务可能不会被消费。
- Dashboard 需要认证和权限。
- 任务失败应记录错误信息。

### 3.12 通知中心

入口：

- 系统管理 / 通知中心
- 系统管理 / 通知管理
- 顶部通知铃铛

用途：

- 普通用户查看自己的通知、未读数、已读和删除。
- 管理员发送系统通知、维护通知模板。

操作：

1. 顶部铃铛查看未读通知。
2. 在通知中心分页查询通知。
3. 标记单条已读、全部已读、删除通知。
4. 管理员发送系统通知。
5. 维护通知模板。

测试重点：

- 审批待办、抄送、拒绝、完成等动作应产生通知或 Outbox 消息。
- RabbitMQ/通知消费者关闭时，主业务流程不应被通知失败阻断。

### 3.13 在线用户

入口：系统管理 / 在线用户

用途：查看当前在线会话，支持强制下线。

操作：

1. 查询在线用户列表。
2. 查看会话详情。
3. 对普通用户执行强制下线。

测试重点：

- 被强制下线用户再次请求应被清理登录态或跳回登录页。
- 不应误踢当前内置管理员的关键测试会话。

### 3.14 日志和消息

入口：

- 系统管理 / 操作日志
- 系统管理 / 登录日志
- 系统管理 / Outbox 消息
- 系统管理 / Inbox 消息

用途：

- 操作日志：查看接口请求、用户、路径、耗时、TraceId、结果。
- 登录日志：查看登录成功、失败、刷新 Token、登出等安全事件。
- Outbox 消息：查看待发布、已发布、失败的可靠消息。
- Inbox 消息：查看消费幂等记录。

测试重点：

- 新增/编辑/删除操作应生成操作日志。
- 登录失败应生成登录日志和登录失败记录。
- 日志中密码、Token、客户端密钥等敏感字段应被脱敏。
- Outbox 失败后应可重试或标记失败。

## 4. 安全中心

### 4.1 安全策略

入口：安全中心 / 安全策略

用途：维护密码复杂度、密码有效期、登录失败锁定、多因素开关、敏感操作校验、IP 黑白名单开关。

操作：

1. 查看当前策略。
2. 修改密码最小长度、数字/大小写/特殊字符要求。
3. 修改登录失败锁定阈值和锁定时间。
4. 开启或关闭敏感操作校验。
5. 开启或关闭 IP 白名单/黑名单。

测试重点：

- 开启敏感操作校验后，涉及用户删除、重置密码、API 客户端密钥、IP 规则等高风险操作应要求验证码。
- 密码策略变更后，新密码校验应按新策略执行。

### 4.2 IP 黑白名单

入口：安全中心 / IP 黑白名单

用途：维护允许或拒绝访问的 IP 规则。

操作：

1. 新增白名单或黑名单规则。
2. 填写 IP 或匹配表达式、说明、启用状态。
3. 编辑、删除规则。
4. 开启对应安全策略后验证访问效果。

测试重点：

- 黑名单命中应拒绝访问。
- 白名单开启后，未命中白名单的来源应被拒绝。
- 测试时避免把当前测试机 IP 锁出系统。

### 4.3 登录失败记录

入口：安全中心 / 登录失败记录

用途：查看用户登录失败次数、最近失败时间和锁定截止时间。

操作：

1. 使用错误密码连续登录。
2. 查看失败记录是否累计。
3. 达到阈值后确认锁定时间。

测试重点：

- 错误密码应记录失败原因。
- 达到锁定阈值后，正确密码也应在锁定期内受限制。

## 5. 审批管理

### 5.1 流程定义

入口：审批管理 / 流程定义

用途：维护审批流程定义、版本、发布状态和设计器内容。

操作：

1. 新增流程定义，填写 `Code`、名称、业务类型 `BusinessType`。
2. 编辑流程基础信息。
3. 点击“设计”进入流程设计器。
4. 保存设计器。
5. 发布流程。
6. 复制流程版本。
7. 停用流程。
8. 删除未发布或允许删除的定义。

设计器支持节点：

- Start：发起人。
- Approver：审批人。
- Cc：抄送人。
- Condition：条件分支。
- End：结束。

当前已落地的审批人解析方式：

- 指定用户。
- 指定角色。
- 发起人本人。
- 表单字段指定人。

当前已落地的审批方式：

- 单人审批。
- 会签。
- 或签。
- 依次审批基础能力。

条件分支可使用表单 JSON 字段，例如 Demo 审批单会传入：

- `amount`
- `departmentId`
- `applicantUserId`
- `applicantUserName`

测试重点：

- 发布前必须有合法 Start/End 节点和连线。
- 审批节点必须配置可解析的审批人。
- 条件节点应配置默认分支。
- 发布后的流程用于新实例，历史实例不应受新版本影响。

### 5.2 业务流程绑定

入口：审批管理 / 业务流程绑定

用途：把业务类型 `BusinessType` 绑定到已发布流程定义。

操作：

1. 新增绑定。
2. 填写业务类型，例如 `DemoApprovalOrder`。
3. 填写业务名称，例如 `Demo 审批单`。
4. 选择已发布流程定义。
5. 启用绑定。
6. 可编辑、禁用或删除绑定。

测试重点：

- 同一业务类型同一时间只能有一个启用绑定。
- 禁用绑定后，不能发起新的该业务审批。
- 已发起流程不应受绑定禁用影响。

### 5.3 待我审批

入口：审批管理 / 待我审批

用途：查看当前用户待处理任务。

操作：

1. 查询待办任务。
2. 打开审批详情。
3. 执行同意，填写意见。
4. 执行拒绝，填写意见。
5. 执行转交，选择目标用户。
6. 执行加签，选择目标用户。

测试重点：

- 非任务审批人不能审批他人任务。
- 同一任务不能重复审批。
- 或签场景中，一人通过后其他待办应取消。
- 会签场景中，应所有人通过后才进入下一节点。

### 5.4 我已审批、我发起的、抄送我的

入口：

- 审批管理 / 我已审批
- 审批管理 / 我发起的
- 审批管理 / 抄送我的

操作：

1. 在“我已审批”查看处理过的任务。
2. 在“我发起的”查看自己发起的实例。
3. 在“我发起的”对允许撤回的实例执行撤回。
4. 在“抄送我的”查看抄送记录并标记已读。
5. 打开审批详情查看任务、抄送、审批记录时间线。

测试重点：

- 审批详情应展示业务标题、流程定义、当前状态、任务列表和记录。
- 撤回后待办任务应取消，业务状态应回写。
- 抄送已读状态应正确变化。

## 6. Demo 审批单端到端测试

入口：示例模块 / Demo 审批单

用途：验证业务单据接入审批流、编号规则、状态机和通知的完整闭环。

### 6.1 前置配置

1. 至少准备两个启用用户：一个发起人，一个审批人。
2. 创建或确认存在 `DemoApprovalOrder` 编号规则。
3. 创建流程定义，业务类型填写 `DemoApprovalOrder`。
4. 设计流程，例如 `Start -> Approver -> End`。
5. 审批人节点选择指定用户或角色。
6. 发布流程。
7. 在“业务流程绑定”中新增并启用 `BusinessType = DemoApprovalOrder` 的绑定。

### 6.2 单据操作

1. 新增 Demo 审批单，填写标题、金额、部门。
2. 保存后状态为 `Draft`。
3. 提交审批。
4. 单据状态应变为 `Pending`，并生成 `WorkflowInstanceId`。
5. 审批人登录，在“待我审批”处理任务。
6. 同意后，单据状态应变为 `Approved`。
7. 新建另一张单据，审批拒绝后状态应变为 `Rejected`。
8. 对审批中的单据执行撤回，状态应变为 `Withdrawn`。
9. 对草稿单据执行取消，状态应变为 `Cancelled`。

状态约束：

- 只有 `Draft`、`Rejected`、`Withdrawn` 可编辑。
- 只有 `Draft` 可删除。
- 只有 `Pending` 且存在流程实例时可撤回。
- 未绑定或绑定已禁用时不能提交审批。

### 6.3 条件分支测试

1. 在流程设计器中添加条件节点。
2. 配置条件，例如 `amount > 10000` 走高金额审批。
3. 配置默认分支走普通审批。
4. 分别提交不同金额的 Demo 审批单。
5. 查看审批任务是否进入不同审批人或不同节点。

测试重点：

- 条件字段来自提交时的表单快照。
- 条件不命中时应走默认分支。
- 缺少默认分支可能导致发布或运行失败。

## 10. 常见问题

### 10.1 登录失败

检查：

- 数据库连接是否正常。
- SeedData 是否执行完成。
- `SeedData:AdminPassword` 是否配置。
- OAuth 客户端 `permission-admin` 是否存在。
- 前端配置的客户端密钥是否与后端一致。
- 是否触发登录失败锁定。

### 10.2 登录后没有菜单

检查：

- 当前用户是否有角色。
- 角色是否分配菜单。
- 角色是否启用。
- 用户是否重新登录刷新权限声明。
- 菜单是否启用且路径/组件正确。

### 10.3 接口返回 403

检查：

- 用户是否拥有对应权限码。
- 后端 `PermissionAttribute` 权限码是否与数据库权限一致。
- Token 是否是权限调整前签发的旧 Token。
- 是否跨租户访问了没有授权的数据。

### 10.4 审批单无法提交

检查：

- `DemoApprovalOrder` 流程定义是否已发布。
- 业务流程绑定是否启用。
- 流程设计器是否保存了合法 Start、Approver、End。
- 审批节点是否配置了有效用户或角色。
- 单据状态是否允许提交。
- 当前用户是否拥有 `demo-approval-order:submit` 和相关流程权限。

### 10.5 Hangfire 或消息不执行

检查：

- Worker 是否启动。
- SQL Server 是否正常。
- RabbitMQ 是否实际启用且容器可访问。
- `RabbitMQ:Enabled`、`EnableConsumers`、`EnableOutboxPublisher` 是否与测试目标一致。
- 队列名称是否匹配。

## 11. 测试风险和注意事项

- 本文档只描述当前代码中已存在的页面、控制器和服务能力；业务规则以后续代码变更为准。
- 本地配置文件可能包含敏感值，测试记录和截图不要泄露密码、Token、客户端密钥、连接串。
- 内置 `admin` 用户和 `SuperAdmin` 角色有保护逻辑，测试破坏性操作时不要尝试绕过保护。
- IP 黑白名单测试可能把当前测试机锁出系统，建议先准备数据库或配置层面的恢复方式。
- RabbitMQ、Redis、Hangfire、Worker 是否启用会影响通知、消息、任务相关测试结果。
- 权限、菜单、角色调整后，普通用户需要重新登录才能验证最终效果。
